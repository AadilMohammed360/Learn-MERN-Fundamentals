React, visually explained

From project files to a living webpage

React starts from the HTML page, enters through main.jsx, builds a tree of components beginning with App.jsx, then renders the result into the page’s root element.

💡

Important idea: React does not paste the contents of App.jsx into the HTML file. The HTML provides an empty mount point; React creates and updates the visible DOM inside it.

01

First, the vanilla JavaScript DOM version

Before React, JavaScript can build visible page content by finding an HTML element, creating DOM elements, adding text, and attaching them to the page.

frontend/index.html — empty destination
<body>
  <div id="root"></div>
  <script type="module"
    src="/src/main.js"></script>
</body>
src/main.js — manually create and attach DOM
// Find the empty destination in the HTML
const root = document.getElementById('root');

// Create real DOM elements
const heading = document.createElement('h1');
heading.textContent = 'Student Management';

const message = document.createElement('p');
message.textContent = 'Welcome to the app.';

// Attach the new elements under #root
root.appendChild(heading);
root.appendChild(message);

getElementById

Finds the existing <div id="root"> in the HTML page.

createElement + textContent

Creates real DOM elements and gives them text. textContent treats text as text, rather than parsing it as HTML.

appendChild

Attaches each created element inside the root so the browser can display it.

↔

Useful comparison: This is the manual DOM work that React takes responsibility for. React’s createRoot(root).render(<App />) is not just an alias for appendChild; it renders a component tree and keeps the DOM in sync when state or props change.

You may see innerHTML used to insert markup as a string, but this example uses createElement and textContent to make the DOM steps visible and avoid treating user-provided text as HTML.

02

The startup pipeline

HTML shell

frontend/index.html

The browser loads this page. Its empty #root element is where React will display the app.

<div id="root"></div>
→
Entry point

src/main.jsx

The JavaScript entry module imports React, styles, and the top-level App, then calls createRoot(...).render(...).

createRoot(rootElement).render(<App />)
→
Browser output

Rendered webpage

React creates the page’s DOM under #root. The browser displays that DOM as the final interface.

#root → React-managed DOM

The browser parses the HTML, loads the module, and React renders the component tree into the root.

03

How the component tree comes together

HTML mount point

frontend/index.html contains the root container:

<div id="root"></div>

It starts empty. React uses this element as the target for rendering.

App.jsx — top-level component Composes the page and coordinates its state and behavior
↓
StudentForm.jsx Inputs and submit action
StudentList.jsx Displays the collection of students
StudentItem.jsx One student row, with edit/delete actions

Example structure for teaching component composition. In this project right now, the form and list are written directly inside App.jsx; they could later be extracted into separate component files.

04

What each file is responsible for

index.html — the host page

Provides the real HTML document and the #root element. It also loads /src/main.jsx as a JavaScript module.

main.jsx — the bootstrap

Finds the root element, creates a React root, and tells React to render <App />. It is the app’s JavaScript entry point.

App.jsx — the composition root

Imports and arranges the page’s components. It can hold shared state and pass data and event handlers to child components through props.

05

See the connection in code

frontend/index.html
<body>
  <!-- React mounts into this element -->
  <div id="root"></div>
  <script type="module"
    src="/src/main.jsx"></script>
</body>
frontend/src/main.jsx
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const rootElement = document
  .getElementById('root');

createRoot(rootElement).render(
  <App />
);
06

How components communicate

Parent imports child App.jsx imports child component files and places them in its JSX.
Parent passes props Data and callback functions flow down to child components as props.
User interacts A child calls a callback prop when a user types, submits, edits, or deletes.
State updates, UI rerenders The state-owning component updates state; React reconciles and updates the affected DOM.
07

The complete picture

1 · HTML

Creates #root

The browser opens the page and provides the mount element.

→
2 · Entry

main.jsx starts React

It locates the root and asks React to render <App />.

→
3 · Components

App tree becomes the UI

React renders App and its descendants into #root, producing what the user sees.

Think of main.jsx as the starter, App.jsx as the page composer, and #root as the destination where React-managed DOM appears. Components form a tree—not a literal pasted or flattened “mega component.”
